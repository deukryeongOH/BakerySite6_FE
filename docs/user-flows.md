# 사용자 플로우 (2026-07-29)

실제 라우트(`app/`)와 각 화면 구현을 기준으로 정리한 3가지 사용자 플로우. `docs/ux-improvement-plan.md`가 이 문서를 기준으로 찾은 개선점 정리본이니 같이 참고할 것. 백엔드가 바뀌어 플로우가 달라지면 이 문서도 함께 갱신.

화살표(→)는 순차 이동, `↳`는 분기.

---

## 1. 일반 회원 (구매자)

**가입/로그인**
1. `/signup` 또는 `/login`(이메일/비밀번호, 또는 Google OAuth) → 로그인 성공 시 `/`(홈)으로 이동
2. 토큰은 `localStorage`에 저장, 하단 탭바(`홈 / 찜 / 주문내역 / 마이`)로 이동

**드롭 구매 (핵심 플로우)**
1. 홈(`/`)에서 오늘의 드롭 카드 확인(오픈/마감까지 카운트다운) → 클릭 → `/drops/{dropId}`
2. 드롭 상세에서 **수량**과 **픽업 가능 날짜**를 먼저 선택 (둘 다 안 고르면 "구매하기" 버튼 비활성화)
3. "N개 구매하기" 클릭 → 대기열 진입(`enter`)
   - ↳ 즉시 `ACTIVE`면 바로 입장 확정
   - ↳ 대기 중이면 순번 폴링(1초 간격) → 내 차례 되면 자동으로 입장 확정
4. 입장 확정되는 즉시 백그라운드로 **재고 선점(`lock-start`) → 장바구니 생성 → 픽업일 저장**까지 자동 처리 → `/order`로 이동
5. `/order`(결제 화면): 상품/픽업일/결제금액 확인, 예치금 잔액 표시
   - ↳ 잔액 충분 → "결제하기" → 주문 생성 → `/order/complete`
   - ↳ 잔액 부족 → "충전하고 결제하기" → `/wallet/charge?returnTo=...` → 충전 완료 후 원래 결제 화면으로 복귀
6. 이 결제 화면을 이탈(뒤로가기/탭 닫기 등)하면 선점했던 재고를 자동으로 반납(`pagehide`/unmount 훅)

**주문 관리**
- `/orders`: 상태별 필터(전체/픽업대기/구매확정/취소) + 페이지네이션 목록
- `/orders/{orderId}`: 픽업 D-day, 결제 정보, `PAID` 상태일 때만 "주문 취소" 가능(취소 시 예치금 환불 + 목록 invalidate)

**예치금**
- `/wallet`: 잔액, 거래내역(충전/결제/환불), 진행 중인 충전 건 안내
- `/wallet/charge`: 토스 결제창 연동 → `/wallet/charge/success` 또는 `/fail`

**찜 & 마이페이지**
- `/wishlist`: `localStorage` 기반(서버 API 없음, memberId별로 분리)
- `/mypage`: 회원정보 조회/수정, 비밀번호 변경, 회원 탈퇴, 로그아웃, **판매자 입점 신청 진입점**

## 2. 판매자

일반 회원과 동일한 계정 체계(별도 SELLER role 없음 — `Seller` 엔티티로 신청 상태를 관리)입니다.

**입점 신청**
1. `/mypage`에서 "판매자 입점 신청" → `/seller/register`
2. 3단계 폼:
   - **1단계** 사업자 인증(사업자등록번호/주소/대표자명)
   - **2단계** 계좌 인증 — 은행 선택(드롭다운) + 계좌번호/예금주 → 1원 송금 인증 요청 → 4자리 코드 입력해 확인
   - **3단계** 베이커리 상호명 입력 후 최종 신청 → 상태 `PENDING`
3. 이미 신청 이력이 있으면 폼 대신 `/seller/dashboard`로 바로 리다이렉트

**승인 대기 → 관리자 승인**(아래 3번 참고) → `APPROVED`가 되면:

**판매자 대시보드** (`/seller/dashboard`)
- 상단에 내 판매자 정보 카드(상호명/사업자번호/정산계좌 — 은행명으로 표시/승인 상태)
- "내 정산" 진입 링크
- "내 드롭" 섹션: 예정/진행중/종료 탭으로 드롭 목록 확인
  - "+ 새 드롭 등록" → `/seller/drops/new`
  - 예정 드롭은 카드에서 바로 수정(`/seller/drops/{id}/edit`)/삭제 가능

**내 정산** (`/seller/settlements`)
1. 월별 정산 목록(기간, 상태 배지, 판매금액/수수료/지급액 요약)
2. 카드 클릭 → `/seller/settlements/{id}` 상세: 요약(판매금액/수수료/조정/순매출/지급액) + 주문 항목별(`lines`) 내역(상품명/수량/수수료율/순정산액)
3. 승인된 판매자가 아니면 "승인된 판매자만 정산 내역을 확인할 수 있습니다" 안내로 대체

**반려된 경우**: 대시보드 카드에 반려 사유가 표시됨. **재신청 플로우는 현재 없음 — 데드엔드**(`docs/ux-improvement-plan.md` §10, `docs/backend-api-requests.md` §5).

## 3. 관리자

역할(role=`ADMIN`)은 FE에 승격 UI가 없고 백엔드에서 부여된 계정으로 로그인하는 것을 전제로 합니다. `/mypage`에 role===`ADMIN`일 때만 "판매자 승인 관리" / "정산 관리" 링크 두 개가 노출됩니다.

**판매자 승인** (`/admin/approvals`)
1. `PENDING` 상태 판매자 카드 목록 조회
2. 카드 클릭 → 승인/반려 컨트롤 펼침(반려 시 사유 입력)
3. 처리 성공 시 해당 카드가 목록에서 자동으로 빠짐(쿼리 invalidate)

**정산 관리** (`/admin/settlements`) — 탭 2개
- **배치 실행/이력**
  1. 기간(시작~종료일) 입력 후 "정산 배치 실행" → 월 정산 배치(Spring Batch) 트리거
  2. 실행 이력 목록이 `STARTING`/`STARTED` 상태가 있는 동안 5초 간격 자동 폴링, 완료되면 폴링 중단
  3. 같은 기간 재실행 시 백엔드 에러 메시지(이미 완료/실행 중 등) 그대로 노출
- **지급 관리** *(정산 ID를 직접 입력해야 함 — 관리자용 전체 정산 목록 조회 API가 아직 없어서 임시로 이렇게 구현돼 있음, `docs/backend-api-requests.md` §3)*
  1. 정산 ID 입력 → 조회 → 해당 정산의 지급 이력 표시
  2. "지급 시작" → 상태 `PROCESSING`
  3. `PROCESSING` 상태 건에 대해 "완료 처리"(외부거래ID 입력) 또는 "실패 처리"(사유 입력)

**공통 가드**: `app/admin/layout.tsx`가 비로그인/비관리자를 각각 `/login`, `/`로 리다이렉트(클라이언트 사이드 가드 — 백엔드 `/internal/v1/settlement-*`에는 아직 서버단 권한 검사가 없다는 점은 `docs/backend-api-requests.md` §4에 별도로 기록돼 있음. FE 가드만으로는 실질적 방어가 안 되는 상태 — `docs/ux-improvement-plan.md` §8).

## 알려진 데드엔드/약점 (요약)

이 플로우들을 코드 기준으로 검증하며 발견한 문제는 `docs/ux-improvement-plan.md`에 항목별로 정리돼 있음. 대표적인 것만 요약:

- 대기열 순번 폴링이 `NOT_FOUND` 상태를 처리하지 않아 영구 정지(§1)
- 결제 페이지 이탈 후 재구매 시도 시 `DR006`으로 영구 차단(§2)
- 결제 화면이 실제 장바구니(TTL/금액)를 조회하지 않음(§3)
- 관리자 정산 지급이 대상 확인 없이 ID 하나로 실행됨(§7)
- 판매자 반려 후 재신청 경로 없음(§10)
