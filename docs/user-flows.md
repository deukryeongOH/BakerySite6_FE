# 사용자 플로우 (2026-07-29 갱신)

실제 라우트(`app/`)와 각 화면 구현을 기준으로 정리한 3가지 사용자 플로우. 이번 갱신은 정산(settlement) 도메인 전면 연동 + 관련 API 갭 대부분 해결(§`docs/backend-api-requests.md` 참고)을 반영한 것. `docs/ux-improvement-plan.md`가 이 문서를 기준으로 찾은 개선점 정리본이니 같이 참고할 것(단, 그 문서의 체크박스는 이번 갱신 내용을 아직 반영 안 해서 일부 항목은 이미 해결된 상태로 남아있을 수 있음 — 하단 "알려진 이슈" 절 참고). 백엔드가 바뀌어 플로우가 달라지면 이 문서도 함께 갱신.

화살표(→)는 순차 이동, `↳`는 분기.

---

## 1. 일반 회원 (구매자)

**가입/로그인**
1. `/signup` 또는 `/login`(이메일/비밀번호, 또는 Google OAuth) → 로그인 성공 시 `/`(홈)으로 이동
2. 토큰은 `localStorage`에 저장, 하단 탭바(`홈 / 찜 / 주문내역 / 마이`)로 이동

**홈 화면** (`/`)
1. 예치금 잔액이 상단 배지로 항상 보임 → 클릭 시 `/wallet`
2. 가장 가까운 예정 드롭 1건을 히어로 카드로 보여줌 — `SCHEDULED`(오픈 전)/`ON_SALE`(판매중) 상태면 오픈/마감까지 카운트다운(시:분:초)이 함께 뜸
3. 그 아래 "다가오는 드롭" 섹션에 나머지 드롭들을 픽업 날짜별로 그룹핑해 가로 스크롤 카드로 나열(`GET /api/v1/drops/upcoming`, 기본 7일치)
4. 예정된 드롭이 하나도 없으면 "예정된 드롭이 없습니다" 안내

**드롭 구매 (핵심 플로우)**
1. 드롭 카드 클릭 → `/drops/{dropId}`
2. 드롭 상세에서 **수량**과 **픽업 가능 날짜**를 먼저 선택 (둘 다 안 고르면 "구매하기" 버튼 비활성화)
3. "N개 구매하기" 클릭 → 대기열 진입(`enter`)
   - ↳ 즉시 `ACTIVE`면 바로 입장 확정
   - ↳ 대기 중이면 순번 폴링(1초 간격) → 내 차례 되면 자동으로 입장 확정
4. 입장 확정되는 즉시 백그라운드로 **재고 선점(`lock-start`) → 장바구니 생성 → 픽업일 저장**까지 자동 처리 → `/order`로 이동
5. `/order`(결제 화면): 상품/픽업일/결제금액 확인, 예치금 잔액 표시
   - ↳ 잔액 충분 → "결제하기" → 주문 생성 → `/order/complete`
   - ↳ 잔액 부족 → "충전하고 결제하기" → `/wallet/charge?returnTo=...` → 충전 완료 후 원래 결제 화면으로 복귀
6. 이 결제 화면을 이탈(뒤로가기/탭 닫기 등)하면 선점했던 재고를 자동으로 반납(`pagehide`/unmount 훅). 이후 같은 드롭을 다시 시도해도 재입장이 막히지 않음(`DropEntry`가 `FAILED`로 전환되고, 대기열 재입장 차단 조건에 `FAILED`/`ENTERED`는 포함돼 있지 않음 — 이전에 우려했던 "결제 이탈 후 영구 데드엔드"는 실제로는 발생하지 않는 것으로 확인됨).

**주문 관리**
- `/orders`: 상태별 필터(전체/픽업대기/구매확정/취소) + 페이지네이션 목록
- `/orders/{orderId}`: 픽업 D-day, 결제 정보, `PAID` 상태일 때만 "주문 취소" 가능(취소 시 예치금 환불 + 목록 invalidate)
- **"지도 보기"/"전화하기" 버튼이 실제로 동작함**: 판매자 주소/전화번호가 주문 상세 응답에 포함돼(`seller.address`, `seller.phoneNumber`) 지도 보기는 구글맵 검색 링크(새 탭), 전화하기는 `tel:` 링크로 연결. 판매자 정보가 없는 예외 케이스에서는 버튼이 비활성화됨.

**예치금**
- `/wallet`: 잔액, 거래내역(충전/결제/환불), 진행 중인 충전 건 안내
- `/wallet/charge`: 토스 결제창 연동 → `/wallet/charge/success` 또는 `/fail`

**찜 & 마이페이지**
- `/wishlist`: `localStorage` 기반(서버 API 없음, memberId별로 분리)
- `/mypage`: 회원정보 조회/수정, 비밀번호 변경, 회원 탈퇴, 로그아웃, **판매자 입점 신청 진입점**. `role === "ADMIN"`이면 "판매자 승인 관리"/"정산 관리" 링크가 추가로 노출됨(관리자 플로우 참고).

## 2. 판매자

일반 회원과 동일한 계정 체계(별도 SELLER role 없음 — `Seller` 엔티티로 신청 상태를 관리)입니다.

**입점 신청**
1. `/mypage`에서 "판매자 입점 신청" → `/seller/register`
2. 3단계 폼:
   - **1단계** 사업자 인증(사업자등록번호/주소/대표자명)
   - **2단계** 계좌 인증 — 은행 선택(드롭다운, 코드는 노출 안 함) + 계좌번호/예금주 → 1원 송금 인증 요청 → 4자리 코드 입력해 확인
   - **3단계** 베이커리 상호명 입력 후 최종 신청 → 상태 `PENDING`
3. 이미 신청 이력이 있으면(반려 포함) 폼 대신 `/seller/dashboard`로 바로 리다이렉트 — **재신청 경로는 없음. 제품 결정으로 이 기능 자체를 만들지 않기로 확정됨**(`docs/backend-api-requests.md` §1, 2026-07-29 보류 결정). 반려 사유는 대시보드 카드에만 표시되고 다음 행동은 제시되지 않음.

**승인 대기 → 관리자 승인**(아래 3번 참고) → `APPROVED`가 되면 대시보드가 아래처럼 확장됩니다:

**판매자 대시보드** (`/seller/dashboard`) — 위에서부터 순서대로
1. 판매자 정보 카드(상호명/사업자번호/정산계좌 — 은행명으로 표시/승인 상태, 반려 시 사유)
2. **오늘 픽업 예정**: 오늘 날짜가 픽업일인 주문들을 상품별로 나열 + 총 수량. 취소된 주문은 제외.
3. **날짜별 픽업 집계**: 오늘부터 7일간의 픽업 수량을 막대 차트로 표시(오늘 칸만 강조색)
4. **최근 정산** 요약 카드: 가장 최근 정산 1건(기간/상태 배지/지급액) 미리보기 → 클릭 시 `/seller/settlements`로 이동
5. **판매내역** 링크 → `/seller/orders`
6. **내 드롭** 섹션: 예정/진행중/종료 탭으로 드롭 목록 확인
   - "+ 새 드롭 등록" → `/seller/drops/new`
   - 예정 드롭은 카드에서 바로 수정(`/seller/drops/{id}/edit`)/삭제 가능

(2·3번 위젯과 5번 판매내역은 모두 `GET /api/v1/sellers/me/orders`라는 같은 API 하나로 굴러갑니다 — 대시보드에서는 이 응답을 픽업일 기준으로 클라이언트에서 집계, 판매내역 화면에서는 목록 그대로 페이지네이션.)

**판매내역** (`/seller/orders`)
1. 상태 필터(전체/픽업대기/구매확정/취소) + 페이지네이션 목록. 각 건에 구매자명/수량/금액/픽업일 표시.
2. `PAID`(픽업대기) 상태 주문에는 "구매확정" 버튼이 있어, 판매자가 실제로 픽업 수령을 확인한 뒤 눌러 `PATCH /orders/{id}/confirm` 호출 → 상태가 즉시 `CONFIRMED`로 갱신(목록 invalidate).

**내 정산** (`/seller/settlements`)
1. 상단에 요약 카드(지급 완료 누적액, 진행중 정산 건수)
2. 상태 필터 탭(전체/정산 대기/보류/지급 중/지급 완료/지급 실패)
3. 월별 정산 카드(기간, 상태 배지, 판매금액/수수료/지급액 요약) → 클릭 시 `/seller/settlements/{id}` 상세
4. 상세: 요약 금액(판매금액/수수료/조정/순매출/지급액) + **정산 상태 타임라인**(정산 확정 → 지급 처리 → 지급 완료, 3단계 스테퍼) + 상태별 안내 문구, 그리고 주문 항목별(`lines`) 내역(상품명/수량/수수료율/순정산액)
   - `PAYING` 상태면 "영업일 기준 1~2일 내 입금됩니다" 안내
   - `ON_HOLD`면 "정산팀에 문의해주세요" 안내
   - **`FAILED`면 실제 실패 사유(`failureReason`)와 실패 시각이 빨간 텍스트로 표시됨** — 백엔드가 최근 payout의 실패 사유를 정산 상세 응답에 포함하도록 갱신돼서, 더 이상 "빨간 배지만 보고 이유를 모르는" 상태가 아님.
5. 승인된 판매자가 아니면 "승인된 판매자만 정산 내역을 확인할 수 있습니다" 안내로 대체

## 3. 관리자

역할(role=`ADMIN`)은 FE에 승격 UI가 없고 백엔드에서 부여된 계정으로 로그인하는 것을 전제로 합니다. `/mypage`에 role===`ADMIN`일 때만 "판매자 승인 관리" / "정산 관리" 링크 두 개가 노출됩니다.

**판매자 승인** (`/admin/approvals`)
1. `PENDING` 상태 판매자 카드 목록 조회
2. 카드 클릭 → 승인/반려 컨트롤 펼침(반려 시 사유 입력)
3. 처리 성공 시 해당 카드가 목록에서 자동으로 빠짐(쿼리 invalidate)

**정산 관리** (`/admin/settlements`) — 탭 2개
- **배치 실행/이력**
  1. 기간(시작~종료일) 입력 후 "정산 배치 실행" → 월 정산 배치(Spring Batch) 트리거
  2. 실행 이력 목록이 `STARTING`/`STARTED` 상태가 있는 동안 5초 간격 자동 폴링, 완료되면 폴링 중단
  3. 같은 기간 재실행 시 백엔드 에러 메시지(이미 완료/실행 중 등) 그대로 노출
- **지급 관리** *(전면 개편됨 — 더는 정산 ID를 직접 입력하지 않음)*
  1. 상태 필터 탭(전체/정산 대기/보류/지급 중/지급 완료/지급 실패) + sellerId 필터 + 페이지네이션이 있는 **정산 목록**이 바로 뜸(`GET /internal/v1/settlements`)
  2. 정산 카드 클릭 → 판매자 ID·기간·판매금액/수수료/조정금액/지급액·상태가 담긴 **정산 요약 카드**가 먼저 보이고, 그 아래 지급 이력이 표시됨(`GET /internal/v1/settlements/{id}`) — 예전에는 이 정보 없이 ID만 믿고 지급을 실행해야 했음
  3. "지급 시작" 클릭 시 판매자 ID·금액·시도 번호가 명시된 **확인 다이얼로그**를 거쳐야 실행됨(무확인 원클릭 방지). 멱등키는 "지금까지의 시도 횟수" 기준으로 결정적으로 생성돼, 네트워크 재시도 시 중복 송금을 만들지 않으면서도 실패 후 재시도는 정상적으로 새 시도가 됨.
  4. `PROCESSING` 상태 건에 대해 "완료 처리"(외부거래ID 입력) 또는 "실패 처리"(사유 입력) — 이미 처리 중인 지급이 있으면 "지급 시작" 버튼이 비활성화됨
  5. "← 목록으로"로 돌아가면 방금 처리한 정산의 상태 배지가 갱신돼 있음

**공통 가드**: `app/admin/layout.tsx`가 비로그인/비관리자를 각각 `/login`, `/`로 리다이렉트(클라이언트 사이드 가드). 백엔드 `/internal/v1/**`에는 이제 `hasRole("ADMIN")` 서버단 권한 검사가 실제로 적용돼 있음이 코드로 확인됨(`docs/backend-api-requests.md` §3 해결됨) — 다만 FE의 localStorage 기반 role 가드 자체는 여전히 우회 가능한 방어라, 실제 접근 통제는 서버 쪽에 있다고 보는 게 맞습니다.

## 알려진 이슈 (요약, 2026-07-29 기준)

`docs/ux-improvement-plan.md`에 항목별로 정리돼 있으나 체크박스는 갱신 전 상태로 남아있음. 이번 세션 기준 실제 상태:

**여전히 열려 있음**
- 대기열 순번 폴링이 `NOT_FOUND` 상태를 처리하지 않아 영구 정지할 수 있음(구 계획 §1)
- 결제 화면이 실제 장바구니(TTL/금액)를 조회하지 않음(구 계획 §3)
- ADMIN 가드가 여전히 `localStorage`의 `role` 값을 그대로 신뢰(구 계획 §8, 서버단은 이제 안전하지만 FE 가드 자체는 미변경)

**이번 세션에 해결/무효화됨**
- `/internal/v1/**` CORS 미설정으로 관리자 정산 화면이 브라우저에서 막히던 문제 → `WebConfig`에 `/internal/**` 매핑 추가로 해결, 브라우저 preflight 재현 요청으로 검증 완료(`docs/backend-bug-reports.md`)
- 결제 페이지 이탈 후 재구매 시 `DR006` 영구 차단 우려(구 계획 §2) → 실제로는 발생하지 않음(확인 완료)
- 관리자 정산 지급이 대상 확인 없이 ID 하나로 실행됨(구 계획 §7) → 목록 UI + 요약 카드 + 확인 다이얼로그 + 결정적 멱등키로 개선
- 판매자 대시보드에 운영 정보 부재(구 계획 §12) → 픽업 위젯/최근 정산 카드 추가로 해결
- 주문상세 지도/전화 버튼 미동작(구 계획 §23) → 백엔드 필드 추가 + FE 연결로 해결
- 판매자 반려 후 재신청 불가(구 계획 §10) → "재신청 기능 자체를 만들지 않는다"는 제품 결정으로 종결(버그 아님)
